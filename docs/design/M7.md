## 1. Objectives

1. **PTX-Subset Abstract Syntax Tree (`PTXModule`, `PTXKernel`, `PTXInstruction`, `PTXOperand`):**
   * Represent parsed PTX virtual assembly in a clean, strongly-typed AST.
   * Model module-level directives (`.version`, `.target`, `.address_size`), kernel signatures (`.visible .entry`), parameter lists (`.param`), register bank declarations (`.reg`), labels, predicated statements, and instructions.
2. **Independent PTX Lexer & Parser (`PTXParser`):**
   * Implement an independent, robust tokenizer and recursive-descent/line parser for the PTX subset.
   * Parse IEEE-754 hexadecimal float literals (e.g., `0f3F800000`), decimal floats, integers, register indices, memory references `[...]`, and branch labels.
   * Accurately track source lines and columns for error diagnostics.
3. **PTX Structural & Semantic Validator (`PTXValidator`):**
   * Verify presence and validity of required module directives (`.version 7.0+`, `.target sm_75+`, `.address_size 64`).
   * Verify register declarations: enforce that every referenced register (`%r<k>`, `%f<k>`, `%rd<k>`, `%p<k>`) is within declared bank bounds (`< count`) or declared as a named register.
   * Enforce strict type consistency between instruction opcodes/type suffixes and operand register types (e.g. `add.s32` must write to `%r`, `add.rn.f32` to `%f`, `setp.*` to `%p`).
   * Verify label uniqueness and referential integrity (all `bra` targets must exist).
   * Verify memory operand types (`ld.global`/`st.global` base address must be 64-bit pointer register `%rd`).
4. **PTX CPU Reference Interpreter (Oracle O3 - `PTXInterpreter`):**
   * Implement a virtual GPU execution environment running over a specified grid dimension (`gridDim`) and block dimension (`blockDim`).
   * Per-thread state emulation:
     * Independent virtual register banks (`%r`, `%f`, `%rd`, `%p`) and named register storage.
     * Special register virtualization: `%tid.x`, `%ctaid.x`, `%ntid.x`.
   * Byte-addressed global memory simulation:
     * Map host `BufferManager` buffers into a simulated 64-bit address space.
     * Global memory load/store operations access simulated VRAM with bounds checks.
   * Parameter ABI emulation:
     * `ld.param` loads scalar arguments and buffer addresses.
     * `cvta.to.global.u64` operates in flat 64-bit address space (identity conversion).
   * Predicated execution: support `@%p` and `@!%p` instruction masks.
   * Strict instruction evaluation matching NVIDIA PTX ISA 7.0 semantics (IEEE 754 round-to-nearest-even float math, two's-complement integer math, division/remainder, conversions, bitwise logic).
5. **Differential Verification ($O_1 == O_2 == O_3 == O_4$):**
   * Enable 4-way differential testing:
     * $O_1$: AST Reference Interpreter
     * $O_2$: TAC IR Reference Interpreter
     * $O_3$: PTX Virtual ISA Reference Interpreter
     * $O_4$: Physical NVIDIA GPU Hardware (via CUDA Driver JIT)
6. **Tooling & CLI Integration:**
   * Support `kcc --run-ptx <input.kc|file.ptx>` to directly parse, validate, and interpret PTX files or compile `.kc` to PTX and execute it.
   * Integrate Oracle O3 into the 8-stage `kcc --pipeline` verifying all 4 oracles produce bit-exact identical output.

## 3. PTX AST Data Architecture

### 3.1 Types and Operands
- **`PTXType`**: `U32`, `S32`, `B32`, `F32`, `U64`, `S64`, `B64`, `Pred`.
- **`PTXOperand`**:
  - `Kind::Register`: e.g. `%r0`, `%f3`, `%rd2`, `%p1`, `%rd_offset`, `%r_param_pred`.
  - `Kind::ImmediateInt`: 64-bit integer literal (decimal or hex).
  - `Kind::ImmediateFloat`: 32-bit floating-point literal (parsed from hex `0fXXXXXXXX` or decimal string).
  - `Kind::ImmediatePred`: boolean literal `0` or `1`.
  - `Kind::SpecialReg`: `%tid.x`, `%ctaid.x`, `%ntid.x`.
  - `Kind::MemoryRef`: base register, optional offset, or parameter name `[_param_x]`.
  - `Kind::LabelRef`: branch target identifier string.

### 3.2 Instructions & Predication
- **`PTXPredicate`**: `regName` (e.g. `"%p0"`), `negated` flag (`true` for `@!%p0`).
- **`PTXInstruction`**:
  - `predicate`: optional predicate mask.
  - `opcode`: `Mov`, `LdParam`, `Cvta`, `Cvt`, `Add`, `Sub`, `Mul`, `MulWide`, `Div`, `Rem`, `And`, `Or`, `Xor`, `Shl`, `Shr`, `Neg`, `Not`, `Setp`, `LdGlobal`, `StGlobal`, `Bra`, `Ret`.
  - `typeModifier`: type tag (e.g. `s32`, `f32`, `u64`, `b32`, `pred`).
  - `roundingModifier`: rounding mode (`rn`, `rzi`).
  - `cmpCondition`: comparison condition (`eq`, `ne`, `lt`, `le`, `gt`, `ge`).
  - `operands`: list of `PTXOperand`.
  - `sourceLine`: source line for error reporting.

## 4. Virtual GPU Simulation Architecture (Oracle O3)

### 4.1 Grid & Thread Scheduling
The interpreter simulates execution of a 1D grid of thread blocks:
```
for ctaid_x in 0 .. gridDim - 1:
    for tid_x in 0 .. blockDim - 1:
        run_thread(ctaid_x, tid_x)
```
Each thread executes independently with its own register state.

### 4.2 Simulated Global Memory Address Space
- Device memory pointers in our system are 64-bit integers (`uint64_t`).
- The interpreter allocates virtual base addresses for each buffer registered in `BufferManager` (e.g. `0x100000000ULL + buffer_index * 0x10000000ULL`).
- A memory map table maps virtual base address ranges back to host buffer storage pointers.
- Global loads (`ld.global`) and stores (`st.global`) compute `offset = addr - base_addr`, verify bounds `0 <= offset < buffer_byte_size`, and perform typed reads/writes.

### 4.3 Parameter Space Emulation
- When a thread starts, kernel parameters are available in the simulated parameter space.
- `ld.param.u64 %rd, [_param_x]` loads the virtual 64-bit base address for buffer parameter `x`.
- `ld.param.u32 %r, [_param_n]` loads the 32-bit scalar value.
- `cvta.to.global.u64 %rd, %rd` is a no-op identity conversion in the flat 64-bit address space.

## 5. Verification and Validation Rules

The `PTXValidator` enforces:
1. **Header Directives:** `.version`, `.target`, and `.address_size` must be present.
2. **Register Declarations:** All registers accessed in instructions must be declared in `.reg` blocks. For numbered registers `%r<k>`, `%f<k>`, `%rd<k>`, `%p<k>`, $k$ must be less than the declared count $N$.
3. **Type Consistency:**
   - Destination of integer ops (`add.s32`, `sub.s32`, etc.) must be `%r`.
   - Destination of float ops (`add.rn.f32`, etc.) must be `%f`.
   - Destination of 64-bit pointer ops (`add.s64`, `mul.wide.s32`) must be `%rd`.
   - Destination of `setp.*` must be `%p`.
4. **Control Flow:**
   - Labels must be unique within each kernel.
   - All `bra` target labels must be defined in the kernel.
5. **Memory Operands:**
   - `ld.global` and `st.global` must use memory reference operands with `%rd` base register.

- 100% test pass rate with zero compiler warnings under `-Wall -Wextra -Wpedantic -Wconversion`.
- All valid PTX corpus programs parse, validate, and execute correctly.
- Invalid PTX programs are rejected with precise error messages.
- 4-way differential testing ($O_1 == O_2 == O_3 == O_4$) passes bit-exact across all test kernels.
- `kcc --run-ptx` and 8-stage `kcc --pipeline` execute seamlessly.
