## 1. Objectives

1. Implement **`SourceManager`** to hold source buffers and provide precise 1-based `line:column` coordinate mapping from byte offsets with $O(\log N)$ line lookup using a line-offset table.
2. Implement **`DiagnosticEngine`** and **`Diagnostic`** formatting producing standard compiler error messages with source snippets and caret markers (`^`), e.g.:
   ```text
   test.kc:4:12: error: unexpected character '@'
       let x = @ + 1;
               ^
   ```
3. Implement **`TokenKind`** and **`Token`** data structures representing all lexical elements of the KC language (keywords, identifiers, literals, operators, comments/EOF).
4. Implement a clean, hand-written **`Lexer`** matching the formal DFA specification:
   * Keywords: `kernel`, `i32`, `f32`, `bool`, `true`, `false`, `if`, `else`, `while`, `for`, `return`.
   * Identifiers: `[a-zA-Z_][a-zA-Z0-9_]*` (longest match).
   * Integer literals: Decimal (`[0-9]+`) and Hex (`0[xX][0-9a-fA-F]+`) with overflow checking fitting within 32-bit signed/unsigned range.
   * Floating-point literals: Decimal with fractional/exponent parts (`1.0`, `0.5`, `.5`, `1e3`, `1.0e-3`, with optional `f` suffix documented and supported).
   * Operators: Arithmetic (`+`, `-`, `*`, `/`, `%`), Bitwise (`&`, `|`, `^`, `~`, `<<`, `>>`), Relational (`==`, `!=`, `<`, `<=`, `>`, `>=`), Logical (`&&`, `||`, `!`), Assignment (`=`), Punctuation (`(`, `)`, `{`, `}`, `[`, `]`, `;`, `,`).
   * Comments: Single-line (`// ... \n`) and multi-line (`/* ... */`) with detection for unterminated block comments.
5. Add CLI flag `--dump-tokens <input.kc>` to `kcc` to emit formatted token streams (`TOKEN_KIND "spelling" [line:col]`).
6. Deliver a comprehensive unit test suite with **$\ge 25$ tests** covering valid token sequences, boundary cases, numeric conversions, comment edge cases, and negative diagnostic cases.

## 3. Architecture & Data Structures

### 3.1 SourceLocation & SourceManager
```cpp
struct SourceLocation {
    uint32_t line = 0;   // 1-based; 0 denotes invalid/unknown
    uint32_t column = 0; // 1-based (UTF-8 column or byte column)
    bool isValid() const { return line != 0 && column != 0; }
};

struct SourceRange {
    SourceLocation begin;
    SourceLocation end;
};

class SourceManager {
public:
    SourceManager() = default;
    void setSource(std::string filename, std::string sourceCode);
    
    SourceLocation getLocation(size_t byteOffset) const;
    std::string_view getLineContent(uint32_t line) const;
    std::string_view getFilename() const;
    std::string_view getSource() const;

private:
    std::string filename_;
    std::string source_;
    std::vector<size_t> lineOffsets_; // Byte offset of the start of each line
};
```
* **Line Table Algorithm:** When source is set, a single scan records indices `0` and each index immediately following `\n`. Given byte offset $k$, `std::upper_bound` on `lineOffsets_` gives the 1-based line number in $O(\log L)$ time. The column is simply `byteOffset - lineOffsets_[line - 1] + 1`.

### 3.2 Diagnostic System
```cpp
enum class DiagnosticLevel {
    Note,
    Warning,
    Error
};

struct Diagnostic {
    DiagnosticLevel level;
    SourceLocation loc;
    std::string message;
};

class DiagnosticEngine {
public:
    void report(DiagnosticLevel level, SourceLocation loc, std::string message);
    bool hasErrors() const { return errorCount_ > 0; }
    size_t errorCount() const { return errorCount_; }
    const std::vector<Diagnostic>& getDiagnostics() const;
    
    // Formats a diagnostic with source line and caret
    std::string format(const Diagnostic& diag, const SourceManager& sm) const;

private:
    size_t errorCount_ = 0;
    std::vector<Diagnostic> diagnostics_;
};
```

### 3.3 Token & TokenKind
* `TokenKind` covers:
  * Control / Special: `Eof`, `Invalid`
  * Keywords: `KwKernel`, `KwI32`, `KwF32`, `KwBool`, `KwTrue`, `KwFalse`, `KwIf`, `KwElse`, `KwWhile`, `KwFor`, `KwReturn`
  * Literals: `IntLiteral`, `FloatLiteral`
  * Identifier: `Identifier`
  * Delimiters: `LParen`, `RParen`, `LBrace`, `RBrace`, `LBracket`, `RBracket`, `Semicolon`, `Comma`
  * Operators:
    * `Plus`, `Minus`, `Star`, `Slash`, `Percent`
    * `Amp`, `Pipe`, `Caret`, `Tilde`, `LessLess`, `GreaterGreater`
    * `EqualEqual`, `ExclaimEqual`, `Less`, `LessEqual`, `Greater`, `GreaterEqual`
    * `AmpAmp`, `PipePipe`, `Exclaim`
    * `Equal`

* `Token` stores:
```cpp
struct Token {
    TokenKind kind = TokenKind::Invalid;
    SourceLocation location;
    std::string_view text;
    union {
        int32_t intVal;
        float floatVal;
    } value{};
};
```

## 4. Lexer Algorithm & DFA Rules

1. **Longest Match (Maximal Munch):** For operators with common prefixes (e.g., `<`, `<=`, `<<`), inspect the next character:
   * `<` followed by `=` $\to$ `LessEqual`
   * `<` followed by `<` $\to$ `LessLess`
   * otherwise $\to$ `Less`
2. **Identifiers vs. Keywords:**
   * Scan `[a-zA-Z_][a-zA-Z0-9_]*`.
   * Check token text against a static keyword lookup table (e.g. `unordered_map` or compile-time `switch` / `std::string_view` comparison).
3. **Number Literals:**
   * If starts with `0[xX]`: Hex integer. Check for valid hex digits; parse with range check.
   * Decimal: Scan digits. If a `.` or `[eE]` is encountered, switch to float literal scanner.
   * Float forms supported: `1.0`, `0.5`, `.5`, `1e3`, `1.5e-2`, and optional trailing `f`/`F` (`1.0f`).
   * Integer overflow: report diagnostic if decimal literal does not fit in `uint32_t` or signed 32-bit range.
4. **Comments & Whitespace:**
   * `//`: consume until `\n` or EOF.
   * `/*`: consume until `*/`. If EOF is reached before closing `*/`, report `error: unterminated block comment` with location pointing to opening `/*`.
   * Newlines increment line counter, reset column counter.
5. **Panic/Recovery on Invalid Characters:**
   * An unexpected character (e.g. `@`, `$`) emits an error diagnostic and produces an `Invalid` token or advances past it, allowing the lexer to continue scanning the remainder of the file without crashing.

## 5. Test Plan & Acceptance Criteria

### Acceptance Gate:
1. **SourceManager & Diagnostic Unit Tests:**
   * Accurate line:column calculation on single-line and multi-line files.
   * Handling of Windows CRLF (`\r\n`) and Linux LF (`\n`).
   * Caret rendering format verification.
2. **Lexer Unit Tests ($\ge 25$ distinct tests):**
   * All keywords correctly identified.
   * Identifiers with underscores and digits.
   * Decimal and Hex integer literals (including 0, boundary values, hex case-insensitivity).
   * Float literal formats: standard, leading dot (`.5`), scientific notation (`1e5`, `2.5e-3`), trailing `f`.
   * All 1-char, 2-char operators and punctuation.
   * Single-line comments ignored; comments at end of file.
   * Multi-line block comments spanning multiple lines with proper line count preservation.
   * Negative: Unterminated block comment reported with line:col.
   * Negative: Invalid characters reported with exact line:col.
   * Negative: Ill-formed numeric literals (e.g. `0x` with no digits, invalid float exponents).
   * Exact token stream verification on a realistic `saxpy.kc` kernel snippet.
3. **CLI Integration:**
   * `kcc --dump-tokens <file.kc>` prints formatted token list to stdout.
4. **Build & Quality:**
   * 100% GoogleTest pass rate on `ctest`.
   * Zero compiler warnings under `-Wall -Wextra -Wpedantic -Wconversion`.

## 6. Risks & Mitigation

| Risk | Mitigation |
|---|---|
| Windows `\r\n` line endings causing off-by-one column counts | Treat `\r\n` as a single newline event in offset table and scanner |
| Float parsing discrepancies between MSVC and GCC | Use standard `std::from_chars` (C++17/C++20 `<charconv>`) for locale-independent, bit-exact floating point and integer parsing |
| Unterminated block comments causing infinite loops | Check for EOF at every character peek within block comment scanner |
