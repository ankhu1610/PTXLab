## 1. Objectives

1. **GPU Hardware Execution Engine (`GPURunner`):**
   * Execute generated NVIDIA PTX virtual ISA modules directly on physical NVIDIA GPU hardware (RTX 5070 Ti Laptop GPU, `sm_120`).
2. **Zero-SDK Dynamic Driver Loading:**
   * Dynamically load NVIDIA CUDA Driver library (`nvcuda.dll` on Windows, `libcuda.so` on Linux) via OS loader APIs (`LoadLibraryA` / `GetProcAddress`).
   * Avoid any build-time or link-time dependency on `cuda.lib` or the monolithic CUDA Toolkit SDK.
   * Graceful degradation: if no NVIDIA GPU or driver is present, fail gracefully with clean diagnostic messages rather than process aborts or missing-DLL dialogs.
3. **Driver-Level Just-In-Time (JIT) Compilation:**
   * Feed PTX strings generated by Milestone 5's `PTXEmitter` directly into `cuModuleLoadDataEx`.
   * Allow NVIDIA's driver JIT compiler to optimize and target the specific physical architecture (`sm_120`).
   * Measure and report JIT compilation latency.
4. **Device Memory Management (VRAM):**
   * Allocate linear device memory buffers on the GPU using `cuMemAlloc`.
   * Marshal and transfer host input data to GPU VRAM using `cuMemcpyHtoD`.
   * Transfer computed output buffers back from GPU VRAM to host memory using `cuMemcpyDtoH`.
   * Ensure leak-free deallocation of all device pointers via `cuMemFree`.
5. **Kernel Launch & Synchronization:**
   * Extract kernel function handles via `cuModuleGetFunction`.
   * Marshal scalar (`i32`, `f32`, `bool`) and pointer (`u64` device address) arguments into standard CUDA Driver ABI pointer arrays.
   * Launch kernels over 1D/2D grids using `cuLaunchKernel`.
   * Block on GPU completion using `cuCtxSynchronize` and capture hardware execution latency.
6. **Triple Differential Testing ($O_1 == O_2 == O_4$):**
   * Verify bit-for-bit equality between:
     * $O_1$: AST Reference Interpreter
     * $O_2$: TAC IR Reference Interpreter
     * $O_4$: Physical NVIDIA GPU Hardware
7. **End-to-End Compiler Pipeline Integration:**
   * Integrate `--run-gpu` flag into `kcc` CLI.
   * Expand `kcc --pipeline` into a full 7-stage pipeline (Tokens $\to$ AST $\to$ Sema $\to$ TAC IR $\to$ Reference Run $\to$ PTX $\to$ Physical GPU).

## 3. Dynamic Driver Architecture

### 3.1 Function Pointer Table

The runner dynamically resolves 17 entry points from `nvcuda.dll`:

| CUDA Driver Function | Signature Purpose |
|---|---|
| `cuInit` | Initialize CUDA Driver subsystem |
| `cuDeviceGet` | Acquire handle to device index 0 |
| `cuDeviceGetCount` | Check count of CUDA-capable devices |
| `cuDeviceGetName` | Query device model name string |
| `cuDeviceGetAttribute` | Query compute capability (`sm_120`) and SM count |
| `cuDeviceTotalMem` | Query total physical VRAM bytes |
| `cuCtxCreate` | Create primary execution context on device |
| `cuCtxDestroy` | Destroy context upon teardown |
| `cuModuleLoadDataEx` | JIT-compile PTX text string into binary module |
| `cuModuleUnload` | Unload compiled module from context |
| `cuModuleGetFunction` | Query kernel entry function pointer by name |
| `cuMemAlloc` | Allocate GPU VRAM buffer |
| `cuMemFree` | Free GPU VRAM buffer |
| `cuMemcpyHtoD` | Copy host data (RAM) to device (VRAM) |
| `cuMemcpyDtoH` | Copy device data (VRAM) to host (RAM) |
| `cuLaunchKernel` | Dispatch grid of thread blocks onto SMs |
| `cuCtxSynchronize` | Await completion of all queued device operations |

### 3.2 Argument Marshaling Protocol

The CUDA Driver API expects `void** kernelParams`, where each element points to the storage of the corresponding kernel argument:

```
kernelParams[0] = &ptrStorage[0];   // Points to 64-bit CUdeviceptr (address in VRAM)
kernelParams[1] = &ptrStorage[1];   // Points to 64-bit CUdeviceptr
kernelParams[2] = &f32Storage[2];   // Points to 32-bit float
kernelParams[3] = &i32Storage[3];   // Points to 32-bit int
```

## 4. Verification and Test Strategy

1. **Hardware Discovery (`DeviceDiscovery`):**
   * Validates device name (NVIDIA GeForce RTX 5070 Ti Laptop GPU), compute capability (`sm_120`), SM count, and VRAM size.
2. **Golden Kernel Hardware Run (`SaxpyGPUExecution`):**
   * Compiles `saxpy.kc` to PTX, launches on GPU, and asserts float outputs match expected values within IEEE 754 precision.
3. **3-Way Differential Parity (`DifferentialTestingO1_O2_O4`):**
   * Runs `saxpy` across $O_1$, $O_2$, and $O_4$.
   * Asserts bit-exact equality: $\text{buffers}_{O1} == \text{buffers}_{O2} == \text{buffers}_{O4}$.
4. **Integer Vector Math (`IntegerVectorMathGPU`):**
   * Tests linear addressing and integer arithmetic operations on GPU hardware.
5. **Multi-Block Grid Scaling (`MultiBlockGridScaling`):**
   * Dispatches 4 blocks $\times$ 64 threads = 256 hardware threads across streaming multiprocessors.
   * Verifies hardware index formula: `tid = ctaid.x * ntid.x + tid.x`.
6. **Graceful Fallback:**
   * Skips tests gracefully on systems without an active NVIDIA GPU driver, keeping CTest green.
